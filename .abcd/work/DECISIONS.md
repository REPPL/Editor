- 2026-09-05 — Canonical identity recorded in `.abcd/development/IDENTITY.md`; README and AGENTS.md openings render from it.
- 2026-09-05 — Opted in to AI disclosure on commits via `.githooks/prepare-commit-msg`.
- 2026-09-05 — The record tiers (`.abcd/development/`, `.abcd/work/`) are committed even though the repo is public; only `.abcd/.work.local/` is ignored.
- 2026-09-05 — First product intent filed as itd-2609051221553568 (draft): HTML-frontend Markdown editor with drag-and-drop assets and a responsive HTML presentation for desktop, tablet, and phone. Hosting shell (Tauri versus browser app) left open pending an ADR.
- 2026-09-05 — The editor is a desktop app; the presentation output is a static website optimised for desktop screens, iPad, and iPhone. Desktop shell (Tauri is the candidate) still needs an ADR.
- 2026-09-05 — Product story fixed as: create on the desktop, edit text on a tablet, present anywhere on the web. Tablet editing assumed to go through a local-network server in the desktop app, no cloud; recorded as an open question on itd-2609051221553568.
- 2026-09-05 — Document model is a book hierarchy: Part = folder, Chapter = Markdown file, Section = H2, Sub-section = H3, ordered by numeric prefix. Supersedes the single-file horizontal-rule model.
- 2026-09-05 — Three exports from one source: website (videos, interactive elements), PDF (print), web slides (Section per slide, Sub-section per step). All optimised for desktop, iPad, iPhone.
- 2026-09-05 — Full Emacs key bindings are the editing binding set, on desktop and on the tablet view with a hardware keyboard. The binding table is to be written into the spec.
- 2026-09-05 — Editor uses no network: the local-network server for tablet editing is dropped. Tablet editing path reopened as a question on itd-2609051221553568.
- 2026-09-05 — Web exports are packaged two ways at the author's choice: one self-contained HTML file with everything embedded (videos optionally external), or an asset folder, optionally zipped, that uploads unchanged to a public web page.
- 2026-09-05 — Publishing: Editor pushes to a GitHub repository served by Cloudflare Pages. One public reader page; each document in a folder named by an unguessable hash, loaded when the reader URL carries the key. Unlisted, not private. Supersedes the folder/zip packaging.
- 2026-09-05 — The single self-contained HTML file is both reader and editor: it imports and exports Markdown only. It is the tablet and anywhere-else editing path; assets are added only in the desktop app.
- 2026-09-05 — Publishing splits into two channels: public code (reader, slides engine, site shell) in GitHub served by Cloudflare Pages; private content (Markdown and assets) uploaded straight to Cloudflare storage under a hash, never through GitHub.
- 2026-09-05 — The PDF is rendered by the publish pipeline and stored beside the document; the desktop app does not export PDF.
- 2026-09-05 — Publishing simplified to one production system: Editor builds, commits under a hash folder, pushes to the production GitHub repository, and returns the hash; Cloudflare Pages deploys a public presenter page plus every document. Supersedes the two-channel design. Repository visibility assumed private, to confirm.
- 2026-09-05 — Assets reachable from anywhere for editing away from the computer is parked as a future feature.
- 2026-09-05 — The maintainer's prototype online article (Org-mode export, Tufte layout, reader controls, easter eggs with Konami reveal) is the reference reading experience; recorded in research/notes/2026-09-05-prototype-article.md. The public presenter domain is magnumesque.com.
- 2026-09-05 — Three exports from one text: Tufte-style online article, Tufte-style PDF, and slides, all using footnotes and native bibliography references from a bibliography file beside the document. Citation syntax assumed Pandoc `[@key]`, to confirm.
- 2026-09-05 — Prototypes are recorded by form only: never their topic, location, or content. The slide prototype's conventions (rule breaks, column splits, layout and source comments, speaker notes) are the reference for slide authoring; slides are authored in the same text, not only derived from the hierarchy.
- 2026-09-05 — An existing personal writing project is the acceptance test for Editor, recorded form-only after three independent model reviews. It adds to the design: split-on-import and a fourth heading level, variants as an in-Markdown marker, referenced-not-copied large assets, a `Video:` fallback line, reader-layer annotations with round-trip conventions, and byte-fidelity on round trip.
- 2026-09-05 — Product grill, round one. Audience: the maintainer first, others later. Article is the rendering to perfect first; slides for a specific talk are the first usable slice. The app is the editor with Emacs bindings ported. Variants are core, selected by link, no switcher. Reader annotations are sidecar files per chapter, private by default, publishable by the author as a public layer. Publishing is per document unlisted or gated.
- 2026-09-05 — Product grill, round two. Markdown canon is Pandoc-compatible plus fenced divs. On disk: folder of chapters with split on import and four heading levels. Shell: Tauri 2. PDF: not Tufte; a modern journal layout rendered by Typst in the pipeline. Hash: stable document id plus versioned content hashes. Assets: embed small, link large, threshold set by the author. Slides: hybrid, hierarchy by default with authored breaks inside. Recorded in brief/02-constraints.md.
- 2026-09-05 — Slides: Section = horizontal slide, Sub-section = vertical slide beneath it, each one's prose its speaker notes; a Sub-sub-section folds into its Sub-section's notes. Supersedes "Sub-section = step" in brief/02-constraints.md.
- 2026-09-05 — Document metadata lives in `document.yaml` at the document root — title, subtitle, abstract, author, affiliation, variants, default variant, bibliography, citation style, theme, asset threshold, and the stable id. A chapter's front matter is chapter-level only. Closes the open question and corrects both ADRs that said "front matter".
- 2026-09-05 — Assets above the deploying host's per-file ceiling (25 MiB, to verify) are uploaded to object storage under the document's id by the publish pipeline, never through git; the manifest records the published URL. Editor holds no storage credential. One publish action, two stores behind it.
- 2026-09-05 — Gated documents carry a committed per-document access file in the production repository, never in the document folder; the pipeline applies the Cloudflare Access policy from it with its own credential. The gate is per document id and covers every version and variant; what a version says never changes, but who may open it follows the document.
- 2026-09-05 — Each variant gets an unguessable path token minted with the id: the stable link is `/<id>/<token>/` and a version is `/<id>/<token>/v/<hash>/`. An id alone renders the empty shell, so no variant's link can be shortened or guessed into another's.
- 2026-09-05 — "The presenter reveals nothing" means the shell, a wrong id, and a missing id render identically — the site's not-found page is the shell — and nothing is listed. It is not a claim about response codes.
- 2026-09-05 — The "no machine in the document" discipline narrows to the author's machine: absolute local paths, local hostnames, usernames, machine-local settings. Published links and gated media URLs are permitted references.
- 2026-09-05 — "Nothing is stored about a reader" binds Editor and the pages it publishes; the access provider necessarily holds the identity of a reader who signs in to a gated document, and the discipline states that carve-out.
- 2026-09-05 — "Network only on publish" means the app touches the network only during a publish Alice started — push, upload, applying access, and following that publish's pipeline until it reports done or failed — and at no other time.
- 2026-09-05 — Device widths fixed at iPhone 390, iPad 820, and desktop 1280 CSS pixels, measured in the current Safari and Chromium engines; the legibility discipline holds them and every spec cites them.
- 2026-09-05 — Citations resolve once: the core's print renderer emits Typst source with references already resolved, and Typst typesets and resolves nothing. Pandoc leaves the pipeline; the core emits Typst source directly.
- 2026-09-05 — Import by split writes one Part named for the document, one chapter per level-one heading with a slug rule and numeric prefixes, any preamble as the first chapter, `document.yaml` minted from the front matter or the first heading, and the source manuscript left untouched.
- 2026-09-05 — Drop is disambiguated by target, stated once in brief/05-internals.md: a Markdown file on a Part becomes a chapter, any file on the text becomes a reference at the cursor, a manuscript arrives through Import, and an edited chapter returns through Re-import, matched by path and an export-time hash.
- 2026-09-05 — Conversion of phone-native images belongs to the drop moment at any size and the original is not kept; the threshold, referenced mode, roots, the manifest, and the upload on publish belong to the referenced-assets intent.
- 2026-09-05 — The insert palette is divider, columns, speaker notes, callout, margin aside, credit, variant block, variant span, video block, citation, footnote, page break, easter egg, opening quotation. The callout and the margin aside are the article intent's.
- 2026-09-05 — A variant block may contain headings, so a Section or Sub-section can belong to one variant alone; other variants omit it from the page, the contents, and the deck with no trace.
- 2026-09-05 — Four moments leave plumbing and become intents — moving through the article by keyboard, setting the threshold and naming an asset root, taking a document off the site, and starting a new document — and a tenth discipline, "Orphan, never guess", binds from phase 7.
- 2026-09-05 — Saving is explicit on the save chord; the modeline marks an unsaved buffer; closing or switching chapter with unsaved changes asks, and an external change to a chapter held unsaved is reported rather than resolved silently.
- 2026-09-05 — The publish log records every publish, including a republish of unchanged content, whose entry points at the hash already on the site and adds no version path.
- 2026-09-05 — The reader controls and the once-only quotation travel into the single HTML file and persist per browser in storage scoped to that file; where storage is unavailable they simply do not persist.
- 2026-09-05 — The article is one page per document, with a contents list covering Parts, Chapters, Sections, and Sub-sections; the app's sidebar shows all five levels.
- 2026-09-05 — An easter-egg marker with no block renders as ordinary text, a block with no marker is left out, both are listed as unresolved, and the opening quotation belongs to the first block of the first chapter alone.
- 2026-09-05 — The one-source discipline forbids a rendering being an input rather than any output being one: exported Markdown and annotation files are inputs by design.
- 2026-09-05 — The canon's permitted forms are five — fenced divs with attributes, heading attributes, image attributes, bracketed span attributes, and HTML comments — with Pandoc's own citations and footnotes not being extensions at all; the degrade discipline forbids content wired by filename convention, not ordering by numeric prefix.
- 2026-09-05 — Severity set honestly on the record: `major` on variant fidelity and on the variants, referenced-assets, per-variant-links, and gated-publishing intents; the rest stay minor.
- 2026-09-05 — The product's own public domain is identity rather than infrastructure, and AGENTS.md's privacy rule now says so.
- 2026-09-05 — The deck carries a credit line at the foot of each slide and no reference list; the article and the PDF carry the generated lists, and a slide's credited key is always one of their entries.
- 2026-09-05 — Restored to the record: video URL and other-file drops, deck input by swipe, tap, and arrow keys, PDF tables and placed images, the named browser engines, conversion originals not kept, and the sidebar's asset count. Video transcripts and full-text search become open questions for later intents; the browse-and-edit-mode split is recorded as an alternative rejected.
- 2026-09-05 — Schemas stay in the internals chapter, which gains a `label` field on annotation files, a `layers/` folder for files received from readers, and the export-time hash that makes re-import conflicts detectable; intents test observable behaviour instead.
- 2026-09-05 — Each ADR's `related_intents` now lists the intents that depend on it.
- 2026-09-05 — Canon settled from the worked examples: an image-only paragraph starts a slide unless it is the first block after a heading; `{.divider}` is allowed on a chapter's H1; a two-line title is one heading; a notes div attaches to the slide whose content it follows; image size by `{width="75%"}`; cross-references by `{#fig:...}`; pipe tables with `: Caption {#id}`; one `assets/` per Part; a `{.refs}` heading for an appendix of sources.
- 2026-09-05 — Answers chosen where the brief was silent: the published deck holds the whole document while Present starts at the current chapter; a chapter title opens the deck; prose under a divider heading becomes its notes; a rule may split anywhere below the chapter title; a footnote prints at the foot of its slide.

- 2026-09-05 — Answers chosen where the brief was silent: the single HTML file carries one variant, reads the whole document, edits one chapter at a time, and holds no annotation surface; getting it to a tablet and back is by whatever means the author already uses.
- 2026-09-05 — Answers chosen where the brief was silent: Alice annotates in the app's article preview; a reader's marks key to the document and its chapter paths and export as one file that is also an import; layers are named, off until turned on, and several can be shown at once; a rehearsal score lasts the sitting.

The pipeline verifies each object's hash against the manifest before deploy. Closes the open question of how large bytes reach a pipeline that cannot receive them through git.
