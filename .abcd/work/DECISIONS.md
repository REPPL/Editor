- 2026-09-05 — When conversion of a phone-native image is unavailable, the drop is refused: nothing is written into the assets folder, nothing into the chapter, and the modeline names the file. No placeholder, because a reference to a picture that is not the picture is a quiet lie inside a portable document, and leaving the original is what the intent forbids. Closes that open question in brief/03-evidence.md.
- 2026-09-05 — Phone-native decoding goes through Apple's ImageIO (objc2-image-io 0.3.2), not a Rust crate: `image` 0.25 excludes HEIF on patent grounds, `libheif-rs` needs a Homebrew libheif and puts an LGPL library in an MIT bundle, and the one pure-Rust decoder is AGPL-only. `sips -s format jpeg` is the recorded fallback.
- 2026-09-05 — EXIF is stripped from every copied image. A JPEG carrying EXIF, IPTC or a comment segment is re-encoded through ImageIO; a PNG or WebP loses only its metadata chunks, losslessly, because turning a lossless image lossy to strip a text chunk costs the author more than it saves them. Every conversion is swept the same way afterwards, since ImageIO writes an EXIF block of its own.
- 2026-09-05 — A dropped file is named to the shell by a nonce, never by a path: Rust receives the native `WindowEvent::DragDrop`, holds the paths for thirty seconds under a nonce, and emits `document://dropped` with the nonce and the drop point in logical pixels. `drop_on_chapter(chapter, nonce)` refuses a nonce it did not mint or one that has expired.
- 2026-09-05 — Above the threshold a dropped file is recorded as a referenced asset naming a root rather than a path — the source's own folder name, or `dropped` where that name would be the author's home folder or account name — and the text carries `asset:<id>`. Resolving the root belongs to map #27; until then the asset is unresolved, which is what brief/05-internals.md section 6 says an unnamed root means.

- 2026-09-05 — The default mapping's image exception is generalised from "the first block after a heading" to "the first block of the slide in force", so a picture that opens a rule's continuation shares that slide instead of making an empty one beside it; a divider slide never takes it, because its face is the headline alone.
- 2026-09-05 — An image slide inherits the face-or-notes placement of the slide it split from, so blocks after a picture on a rule's continuation stay on the face and blocks after a picture under a heading go to the notes. Without it the bullets under the second picture of `examples/presentation/01-slides/01-...` would leave the audience's slide.
- 2026-09-05 — The deck runs reveal.js with `disableLayout: true` over Editor's own `src/core/render/slides.css` and loads no reveal theme: the theme fixes a font size, and a slide that reflows at the reader's width is what "legible on three device classes" costs. Exact visual placement is not available, which `03-evidence.md` already records as the price paid.
- 2026-09-05 — Inline content is rendered by the render layer, not by the parse: `src/core/render/html.ts` holds the escaping, the inline nodes, and the block shapes a deck and an article share, and each renderer reads its own column of `canon.ts` over it.
- 2026-09-05 — The stable id, each variant token, and the version hash are sixteen bytes written as RFC 4648 base32, lower-cased and unpadded: twenty-six characters over `[a-z2-7]`, one grammar for every published path segment. Base32 rather than hex because the production repository is checked out on a case-insensitive file system; base32 rather than base64url because the alphabet omits `0`, `1`, `8` and `9`. The brief's illustrative sixty-four-bit `id:` in 05-internals.md section 1 is corrected and gains `variant_tokens:`, and section 9's open question about the three lengths is struck.
- 2026-09-05 — The article skeleton is built in phase 1 rather than waiting for its own intent: the deck bundle's `src/core/render/article.ts` emits it unstyled, the publish build wraps it as the version folder's `index.html` with a minimal legible stylesheet, and intent 9's later spec inherits the file rather than starting one. One parse, two renderings, from the first slice.
- 2026-09-05 — The key log built for the Emacs-chord spike is kept in the shipped app behind `C-h k` rather than being thrown away with the spike: it is the only way an author can see what a chord reached, and it is what a bug report about a keyboard is made of.
- 2026-09-05 — Raw HTML in a chapter is escaped by every rendering and kept verbatim by the parse. A chapter is a file and a file can come from anywhere — a dropped Markdown file becomes a chapter — so the tree keeps what the author wrote, because a plain tool reads the same file, and no renderer ever hands it to a browser as markup. Recorded as a `Raw HTML` row in brief/05-internals.md section 3 and in `src/core/canon.ts`.
- 2026-09-05 — Speaker notes are a split view inside the present window, opened with `s`, not reveal.js's own speaker popup. That popup calls `window.open("about:blank")` and writes an inline-script document into it; an `about:blank` popup inherits its opener's content policy, and the present window's is `script-src 'self'`, so the script never runs. Relaxing the policy would relax it for the window that renders the author's own Markdown, which is the one window that must not be relaxed.
- 2026-09-05 — A copied JPEG is never re-encoded. EXIF, IPTC and comment segments are stripped losslessly from the byte stream, so the compressed scan reaches the assets folder exactly as it left the camera; re-encoding survives only for a phone-native conversion, where it is unavoidable. This replaces the earlier rule that re-encoded a copied JPEG carrying metadata.
- 2026-09-05 — `serde_yml` is replaced by `serde_yaml_ng` 0.10.0, pinned. `serde_yml` is a fork of the archived `serde_yaml` and carries RUSTSEC-2025-0068 and RUSTSEC-2025-0067 through its `libyml` backend, at the boundary where the shell reads an untrusted `document.yaml`. `cargo audit` now runs as part of `npm run lint` and reports zero vulnerabilities.
- 2026-09-05 — A construct's phase has one source: the `phase` column of `src/core/canon.ts`. `src/core/inserts.ts` names its canon row and reads the number from it, so the palette cannot offer a construct in a phase the placement table has not seeded, and a later phase changes one table rather than two.
- 2026-09-05 — Front matter follows Pandoc's rule with one tightening: the opening `---` may not be followed by a blank line, and the first line inside must look like a YAML key or directive. Without it a chapter opening with a slide split loses its first slide, and a chapter opening `---` above a heading would be read as metadata Pandoc itself would then fail on.
- 2026-09-05 — A `.variant` div or span whose `variant` is empty is marked but unresolved, not "every variant": it belongs to a reserved name no author can write, so text the author has not finished addressing is rendered into no variant rather than into all of them.
- 2026-09-05 — Gated stays selectable and is recorded, rather than being disabled and refused as the publish spec says. The flag is the history of the choice Alice made at each publish; phase 1 enforces neither gate, and the panel says so in a line beside the choice — `GATED_NOTE`, "recorded in the publish log and not enforced in phase 1". Recorded as a departure from the spec's "Gated present and disabled", because a control that records the truth is worth more than one that is greyed out.
- 2026-09-05 — The publish panel takes `C-c C-l`, not the `C-c C-p` its spec names: `C-c C-p` is Present's row in the binding table, and one chord cannot be two commands. The spec's Panel section is the departure.
- 2026-09-05 — The dry run is a second command, `publish_dry_run`, rather than a `dry_run` field on `PublishRequest` as the spec's command table has it. One request shape that can ask for either makes the network-touching path and the network-free path the same call site; two commands make the capability boundary the command name.
- 2026-09-05 — A published version carries only the picture formats the app reads — `ASSET_EXTENSIONS` — held at both ends: `src/publish/build.ts` refuses any other reference and reports it, and `stage_version` refuses any copy whose source or target carries another extension. A local video source is therefore a build refusal in phase 1 rather than a file on the site.
- 2026-09-05 — No rendering writes a `style` attribute. The site serves under `style-src 'self'`, which drops one unread, so a declared column share or picture width reaches the page as `data-width` — a whole percentage on a scale of fives — and a pipe table's alignment as `data-align`, with the rules in `slides.css` and `presenter/article.css`. A deck that laid itself out inline would have collapsed at the link while looking right in the app.
- 2026-09-05 — A publish pushes whenever `HEAD` is ahead of the remote-tracking branch, not only when this publish committed. A publish whose push failed leaves a commit behind, and the retry writes nothing new — so the old rule skipped the push and then recorded links the site had never received.
- 2026-09-05 — `check_deploy`, the one outbound call in the crate, is gated on `PublishInProgress`: the publish command opens a ten-minute window on the hash it pushed, and a poll for any other hash, or outside that window, is refused before a request is built.
- 2026-09-05 — The publish remote must be a name `git remote` lists, never a URL, and `GIT_PROTOCOL_FROM_USER=0` is set on every git invocation: the settings come from the web view, and a remote naming `ext::` or another local transport would run a command of its own.
- 2026-09-05 — The site's base URL must be `https`. An unlisted link is protected by being unguessable, and `http` puts it on the wire in clear.
- 2026-09-05 — A second drop of the same bytes into another Part copies them again rather than writing a reference that climbs out of the Part. A Part is self-contained: `../01-part/assets/x.jpg` is a reference the publish build refuses and one that breaks the moment either Part is moved. The manifest therefore carries one entry per copy, matched on the whole digest and the path rather than on the sixteen-character id.
- 2026-09-05 — GIF comment and application blocks and SVG comments, metadata elements and local-path attributes are stripped like EXIF; an AVIF that declares EXIF or XMP is refused instead, because taking a box out of an ISO base media container means rewriting every offset through it. A JPEG whose marker walk goes wrong is treated as carrying metadata rather than as carrying none.
- 2026-09-05 — A phone-native decode is capped at 64 MiB of source and 80 megapixels decoded. A decode is the one place a dropped file's own bytes decide how much memory Editor asks for, so the ceiling is stated rather than discovered.
- 2026-09-05 — The article's contents list covers every chapter, and each chapter's ids carry a prefix of its own (`c1-`, `c2-`, …). An outline id is unique within one chapter only, and the article is one page per document, so without the prefix two chapters opening the same way would send both contents entries and both footnote anchors to the first one.
- 2026-09-05 — A rendering writes an `href` only for `http`, `https`, `mailto` and a relative reference. A chapter is a file and a file can come from anywhere, so an address in one is the author's text: a `javascript:` or `data:` video source is listed as its own words and handed to no reader's browser.
- 2026-09-05 — Present builds the document's default variant, carried on `DeckSource` from the shell, and the renderers filter `.variant` spans as well as `.variant` blocks. Otherwise the deck rehearsed and the deck published were two different decks, and a picture inside a variant span shipped in every variant's assets.
- 2026-09-05 — A publish refuses a dirty buffer, a chapter that would not read, and a document that declares no variant, before anything is built. A version at a public link cannot be taken back, and the rule lives in `documentForPublish` where it is testable rather than in the shell's entry point where it was not.
- 2026-09-05 — `capabilities/present.json` says plainly that Tauri's capabilities do not gate the application's own commands: every command in `generate_handler!` is reachable from either window, and what keeps the present window to `pending_deck` and `read_asset` is the page it loads. The earlier description claimed an isolation the file does not provide.
- 2026-09-05 — The fenced-div canon is read by a hand-written markdown-it block rule in `src/core/markdown.ts` rather than by `markdown-it-container`, which is therefore not a dependency. The canon writes nested divs with three colons at every level, as Pandoc does; `markdown-it-container` closes the outer div at the first bare `:::`, which turns the canon's own columns example into three sibling divs and swallows the paragraph after it. The rule counts opening and closing fences instead.
- 2026-09-05 — The publish log records the first sighting of a version at its link as `seen_at_link` on the entry, replacing the earlier `deploy` field: it is a stamp on the entry the publish wrote rather than a second record of the same publish, and `record_seen_at_link` writes it once.
- 2026-09-05 — The core's own `deckDocument` envelope and the no-op `siteResolver` alias are removed. The envelope that ships is the site build's, because the site's `script-src 'self'` forbids the inline script the core's envelope started the engine with, and a second envelope nothing writes is a second answer to one question.
- 2026-09-05 — `docs/reference-the-markdown-canon.md` is generated for real: `tools/generate-canon-reference.mjs` reads `src/core/canon.ts` and `src/core/inserts.ts` through Vite's SSR loader — the same modules the program imports, so the page cannot disagree with it — and writes the forms and the placement table between markers, leaving the hand-written prose alone. `npm run lint` fails when the page is stale, and `npm run docs:canon` rewrites it.
- 2026-09-05 — Option is Meta, so an Option keydown never produces text. `src/editor.ts` claims, at the lowest precedence, any Option keydown whose `key` is one character or `Dead`, and cancels the `compositionstart` and `beforeinput` events that follow; keys that produce no text (`M-Up`, `M-Backspace`) are left to the keymaps that bind them. macOS composes `ƒ`, `∂` and five dead-key accents on Option, and an editor that reads Option as Meta cannot also let it type. The key log therefore reports *claimed* and *handled* separately: an unbound Option chord is claimed and not handled.
- 2026-09-05 — The key spike's manual checklist gains an automated half behind two environment variables, `EDITOR_OPEN_FOLDER` and `EDITOR_KEY_LOG`, both unset on every ordinary launch. The log path is resolved in the shell from the launching environment and confined to the application's cache directory or the system's temporary directory, because the web view is a trust boundary and the page must not be able to name the file it writes to.
