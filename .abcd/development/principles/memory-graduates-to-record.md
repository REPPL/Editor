# Memory graduates to the record

## The convention

A lesson whose "why" is a correction any agent should receive belongs in this
repository's committed record — the `AGENTS.md` conventions section, a custom
domain in `.abcd/rules.json`, or a ledger capture. Local agent memory is for
facts about one person and one machine. A memory item recalled twice is a
graduation candidate.

## Why it earns its keep

A correction held only in one operator's local memory is a correction the next
agent, the next machine, and every collaborator will not receive. It will be
rediscovered, at the cost of the mistake that prompted it the first time. The
record is the only place a lesson is durable, reviewable, and visible to
someone who was not there.

The split is not about importance. "The maintainer prefers reviews run by three
models" is a fact about how one person works and belongs in their memory. "Never
fix ahead of an armed detector" is a correction any agent should receive and
belongs in the rules. Confusing the two either clutters the shared record with
one person's habits or hides a shared rule where only one machine can see it.

## What it costs

A judgement call every time something is worth remembering, and the discipline
to make it at the moment of writing rather than later. Graduating too eagerly
fills the committed record with things that were true once; graduating too
rarely is the failure this convention names.

## How to tell it is being followed

- A rule an agent is corrected on twice that still lives only in local memory.
- A local memory item that names a repository convention rather than a person or
  a machine.
- A committed rule that names one operator's preference, which is the mirror
  failure and clutters what everyone reads.
- A recalled memory that turns out to describe a file, flag or function that no
  longer exists — memory records what was true when written, and is verified
  against the tree before it is acted on.
