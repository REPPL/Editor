# ADR-2609051324167479: The PDF is rendered by Typst in the publish pipeline in a journal layout

## Context

The maintainer first wanted a Tufte PDF, then decided against Tufte for print in favour of a modern academic-journal layout with strong tables and numbered references. The PDF is produced in the pipeline, never in the app. Candidates were Pandoc with LaTeX, a headless browser printing the article, and Typst.

## Decision

The pipeline renders the PDF with Typst, using one built-in journal-style template. The shared TypeScript core emits the Typst source directly from the document tree, with every citation and reference already resolved against the same BibTeX file the article and the deck read; Typst typesets and resolves nothing, so there is one citation resolver in the design and not two. Page-break comments in the source are honoured; slide-only constructs are ignored. Each variant renders to its own PDF, stored beside the version and linked from the presenter.

## Alternatives Considered

1. Pandoc plus LaTeX with a journal class. The canonical route with the most templates, at the cost of a TeX toolchain in CI and slower builds. Rejected by the maintainer in favour of the lighter toolchain.
2. A headless browser printing the article with a print stylesheet. One renderer for web and print, but footnotes, page breaks, and tables are weaker. Rejected.
3. Converting to Typst through Pandoc rather than emitting it from the core. One less renderer to write, but a second tool that resolves citations, which is exactly the disagreement between renderings the design forbids. Rejected.

## Consequences

CI needs Typst, a single binary, and nothing else. The core carries a print renderer alongside its two web renderers, and any disagreement between them is one bug in one place. The journal template is Editor's own or one of Typst's published ones; that choice is open in the brief's evidence chapter. Dropping Tufte from print removes the margin-note problem entirely from the PDF path.
