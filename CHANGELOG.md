## 0.2.1 — 2026-09-06

A patch cut, made the morning after 0.2.0, from the maintainer's first sitting at the 0.2.0 release app. It ships one intent — the editing surface's type grows, shrinks and resets from the keyboard — and resolves the two ledger bugs the sitting found in the present window, both of them release-only failures that every test had passed over: the shipped window mounted a deck with no engine behind it, and once the engine was there, every slide but the first sat stacked below the window. Each line below cites the record it reports; the intent names its closed spec.

### Added

- **Make the text bigger or smaller from the keyboard.** `C-x C-=` grows the editing surface's type by one step of 1.2, `C-x C--` shrinks it by one, and `C-x C-0` puts it back to the size the app opened at. Only the words being written change size: the sidebar, the modeline, the keys panel and every other element on the page stay exactly as they were, and the present window's deck opens at its own size whatever the surface is set to. The range is five steps either way, from about 40 % to 249 % of the default; a chord pressed at a bound leaves the size where it is and the modeline says so. After each step the modeline reads the scale as a percentage for a moment and then returns to showing the position and mode. The scale is remembered per machine, as `text_scale` in the settings file in the application's own configuration directory, and read back when the app starts; a value edited by hand to something outside the range is clamped rather than refused, so the surface opens at a size the author can still read. Nothing is written to the chapter or to `document.yaml`, the buffer is not marked as changed, and the settings panel gains no field. The three commands — Bigger text, Smaller text, Default text size — are rows in the binding table, listed in the keys panel and under `M-x`, and because each sits behind the `C-x` prefix, `C--` on its own still redoes and `C-=` on its own stays unbound. (itd-2609061141039863, spc-2609061145242761)

### Fixed

- **The shipped app's present window navigates.** In the 0.2.0 release app `C-c C-p` shows a single page and no arrow moves to another slide. The present log from the maintainer's window records `engine: absent` on every mount: the window loaded the vendored UMD build of reveal.js as a module script, and the bundler took that file's CommonJS branch and exported the engine as a module, assigning no global, while the dev server and the jsdom test both ran the branch that does. The window now imports the engine's ES-module build, which means the same thing to the bundler, the dev server and the test runner; the bundle check asks the emitted present chunk whether the engine is in there, whether the accessor resolves to it, and whether the mount takes it; and a launch switch opens the present window at start so a built binary can prove itself. Proven on the built binary: the present log reports five slides, the deck on the first of them, and the engine answering every method the page drives it through. (iss-2609061132369973)
- **Every slide is shown in turn, not stacked below the window.** With the engine mounted, the arrows moved the index but only the title slide could be seen: the log showed every slide `display: block` and the slides box three windows tall, because reveal.js writes `display` inline on each slide within view distance and overrides a stylesheet that hides by `display: none`. Every section now sits absolutely over the stage, the present one visible and the rest hidden by `visibility`, a property the engine never writes; a slide longer than the stage scrolls inside itself; and the present log records visibility and text length per slide, which is how the fix was proven on the built binary. (iss-2609061209123970)

### Decisions taken

No new architecture decision record; three dated lines appended to the decision log, `.abcd/work/DECISIONS.md`, after the 0.2.0 section, all on 2026-09-06.

- **The type scale is a property of the CodeMirror view alone.** Five steps of 1.2 either way, bounded at about 0.40 and 2.49 of the default, applied as a theme on `.cm-editor` held in a compartment at `Prec.highest`, because the surface's base theme sets `fontSize` on the same selector and without the precedence the two rules tie and the base one wins. The step is clamped in the page and again on read, so a `settings.json` edited by hand to 40 opens a surface the author can still read. `C-x C-0` needs one piece of surgery: the Emacs package reads Control-and-a-digit as the start of a numeric argument before it consults its own key chain, so the chord set a count and left the chain half-open; the guard in `src/emacs.ts` answers it only when the chain is already open and the chord is one Editor registered itself, beside the `REBOUND` list that already covers the package's other unreachable spellings.
- **The present window imports the deck engine as an ES module** rather than reading the `Reveal` the UMD build assigns to `globalThis`. The UMD file means one thing to a bundler, another to a dev server and a third to jsdom, and the bundler's reading assigns no global at all, so the shipped window mounted a deck with no engine while every check stayed green. Both builds stay vendored: the app's window goes through a bundler and the published site and the single-file export serve the UMD raw under `script-src 'self'`, so neither can use the other's. The ES-module file's `sourceMappingURL` comment is cut on every refresh and its half-megabyte map is not vendored. `tools/check-bundle.mjs` asks the emitted present chunk three questions — the engine is in there, the accessor resolves to that engine, and the mount takes that accessor as a parameter default — because every source-level check passed on the build that shipped.
- **The launch harness stays live in release builds** rather than compiling out under `debug_assertions`. `EDITOR_OPEN_FOLDER`, `EDITOR_KEY_LOG`, `EDITOR_PRESENT_ON_OPEN` and `EDITOR_PRESENT_LOG` are what produce the logs a release-only failure is diagnosed from — the last three bugs came out of runs against the release binary — and a switch that exists only in a debug build cannot answer a question about the shipped one. The surface it widens is confined: every switch is read once at start from the process environment and never from the page, the key log is refused unless it lands in the application's cache directory or the system's temporary directory, the page is told whether a log is being written and never where, and each switch is off unless a run asks for it in words (`1`, `true`, `yes`, `on`; `0`, `false`, `no`, `off`; anything else refused with a warning). An open ledger entry holds the choice for the maintainer; this is the current one.

## 0.2.0 — 2026-09-05

The second cut, made the same day as the first, after the maintainer sat at the running app. It ships three intents — the keyboard reaches the sidebar and every panel, the deck and the article export to a folder, and the binding table gains the prose vocabulary with `M-x` and dabbrev — and resolves five ledger bugs the sitting found, chief among them a bundler that had been dropping the whole Emacs keymap from the shipped app while every test passed. Each line below cites the record it reports; the three intents name their closed specs.

### Added

- **Move between the editor and the sidebar without the mouse.** `C-x o`, or `C-x C-o` without lifting Control, moves the keyboard from the text to the sidebar, then to whichever panel is open — the keys panel, the insert palette, the publish panel or settings — and back to the editor, in that fixed order, and the modeline names the pane that holds it. In the sidebar the open chapter's node starts highlighted; `C-n` and `C-p` walk the tree through Parts, Chapters, Sections, Sub-sections and Sub-sub-sections, `C-f` and `C-b` (or Right and Left) expand and collapse a node without opening anything, Return opens that chapter scrolled to that heading and hands the keyboard back with the cursor on the heading, and `C-g` returns to the text with nothing opened and the cursor where it was. Every chord in the flow is a row in the binding table, listed in the keys panel; the same chord is next line in the text and next node in the tree, never both, because only one pane holds the keyboard. At 820 and 390 CSS pixels `C-x o` slides the drawer open and Return or `C-g` closes it. (itd-2609051921482691, spc-2609051925374395)
- **Export what I have made to a folder I choose.** `C-c C-e` opens a panel listing five exports. Three write now — the deck as a folder, the article as a folder, and a dry run of a publish — and each states the folder it creates and every file it puts there before anything is confirmed; the single HTML file and the journal PDF are listed as not yet available with the phase each arrives in, and neither can be confirmed. The shell's own folder dialog picks the destination; a destination inside the document folder, the application's cache or a staging tree is refused with the reason stated, and a failed export takes its own folder away again. An exported deck sits at `slides/index.html` with the engine under `presenter/` and the images beside it under names that need no escaping, is built by the one builder the publish uses, and runs from disk with the network disconnected; its assets and slide markup are byte-identical to the staged version's and its page differs only in the attributes that point at the chrome beside it. The dry-run row stages the version a publish would push and opens that folder in the Finder. No export writes into the document folder, names the machine, or touches the network; `C-g` closes the panel with nothing written. (itd-2609051922232742, spc-2609051927564472)
- **Edit prose with the Emacs commands my hands already know.** Seventeen rows join the binding table and the keys panel. `M-q` fills the paragraph under the cursor to the document's `fill_column` (default 80), keeps any hard break the author wrote, changes no byte outside that paragraph, and refuses inside a fenced div, a pipe table, a code fence or on a heading, saying so in the modeline. `M-t` transposes words and `C-x C-t` lines; `M-c` capitalises a word; `M-a`, `M-e`, `M-{` and `M-}` move by sentence and by paragraph, a sentence ending Emacs's way at a full stop and two spaces or a line break; `M-^`, `M-SPC` and `M-\` join lines and tidy the surrounding space; `M-z` zaps to a character; `M-r` puts the cursor in the middle of the view; `M-@` marks the word. `M-/` completes the word being typed from the document's own words and cycles through the candidates on repeat, putting back the case that was typed. `M-x` opens a command palette over every row of the table and every insert form, filtered as you type, and runs the one chosen; `C-h k` and a chord name that chord in the modeline. `C-x C-c` quits, and when a chapter has unsaved changes it first asks in the window with a two-row overlay that opens on "Keep editing", so `C-g`, Escape or Return leaves the edits intact. The Markdown is what it was: no command writes outside the spans it names. (itd-2609051934109483, spc-2609051938278499)

### Fixed

- **The shipped app carries the Emacs keymap.** The package that installs the keymap marks its two installing calls pure, and both the dev pre-bundle and the release build honoured the annotation and dropped them, so the running app answered no Emacs chord — Option-f and every Meta chord did nothing — while every test passed against the unbundled source. The build now keeps that code, a bundle check fails the build when the keymap is missing, and the modeline reports `no keymap` if it ever is. Option is read as Meta: an Option chord never types `ƒ` or starts a dead-key accent, and the key log reports a chord as claimed and as handled separately. (iss-2609051914327928)
- **`C-/` undoes.** The same absent keymap was the cause; the chord is derived from the physical slash key, so undo on Control-slash reaches the editor. (iss-2609051930593419)
- **The present window shows the deck.** `C-c C-p` opened a window that stayed empty, and after one arrow press showed the first slide's title and nothing else. The engine is synced and moved to the first slide after every mount, and the opening slide is marked present in the markup, so the window opens on the deck. (iss-2609051915021301)
- **Type in the present window grows with the window.** The deck's type scales with both viewport axes and no fixed canvas, and the back control is drawn only when there is a slide to go back to. (iss-2609051919515730)
- **An overlay that loses the keyboard closes.** With the quit confirmation open, `C-x o` and then Return in the editor quit and discarded the unsaved edits, because the overlay left behind kept its key listener; the same held for `M-x`, the insert palette, the prompts and the export panel. Cycling away from an overlay now closes it, cancelled — for the quit question, that means keep editing — while the publish and settings panels, which have no key reader of their own, stay open across the cycle. (iss-2609052115254279)

### Decisions taken

No new architecture decision record; twenty-nine dated lines appended to the decision log, `.abcd/work/DECISIONS.md`, after the 0.1.0 section, all on 2026-09-05.

- **Option is Meta.** An Option keydown never produces text: the editor claims, at the lowest precedence, any Option chord whose key is one character or a dead key and cancels the composition that follows, because macOS composes `ƒ`, `∂` and five accents on Option and an editor that reads Option as Meta cannot also let it type. The key log reports *claimed* and *handled* separately.
- **The toolchain does not honour `/*@__PURE__*/`.** `treeshake: { annotations: false }` at both halves of the build, a bundle check that follows the entry chunk's imports and fails only when no loaded chunk carries the keymap, and a modeline that says `no keymap` — because a console error is seen by no one who is not already looking.
- **Focus is a model of its own.** Three panes in one fixed order; the binding table gains a second scope rather than a second table, so `C-n` is next line in the text and next node in the tree without ambiguity; one document listener reads the panes the editing surface cannot hear and feeds its half-typed prefix to the modeline's own cell; a panel joins the cycle by registering a focus contract and nothing else; the pane the keyboard is in is the editing *surface*, so CodeMirror's search panel counts as the editor; `other-window` moves to owner `editor` and ships in the `document` group, a recorded departure from its spec's table.
- **An overlay that loses the keyboard is closed, not left open**, and `M-x` offers `editor`-scope rows only, with `runBinding` refusing any other scope, because the six sidebar rows the palette once listed inserted newlines instead of opening chapters.
- **The quit question is asked in the window.** A two-row overlay in the application's overlay host, opening on "Keep editing" so the destructive answer is never the one a reflex reaches; the window-close path keeps the native dialog, and adopting the overlay there is a later intent's decision.
- **The export is a folder the author chooses**, reversing the morning's "single HTML file is the only local artefact"; the single file stays intent 17. The deck's page sits at `slides/index.html` with the chrome under `presenter/`, so the exported folder is shaped like a published version folder and the two differ only in the chrome base. The destination is not the page's to name: the shell opens the dialog and holds the answer under a nonce good for one export and thirty seconds; the export refuses the cache and both staging trees, creates its folder with `create_dir`, removes it again on any failure, and reveals the folder it actually wrote. The intent's byte-identity criterion is narrowed to assets and slide markup, with the deck page differing only in the chrome attributes — the orchestrator's call under the standing authorisation, which the maintainer may strike.
- **The prose commands.** `fill_column` (default 80) joins the document metadata, and the byte-fidelity rule now states that a command the author invokes on purpose edits exactly the spans it names. Filling keeps a hard break. The sentence rule ships as `sentenceEndDoubleSpace`, defaulting to Emacs's own, in code and tests but in no panel, and where its off switch lives stays open. `M-x` and `M-/` come off the suppression list; the list overlay is shared by the insert palette, the command palette and the quit confirmation; a prompt with an `onKey` hook listens on the window, one node above the pane cycle's reader; `C-h k` answers against the editor scope; `M-z` reads a chord, not a keystroke, and refuses Control, Option and Command as a target; prose commands read through `state.sliceDoc` so a `\r\n` chapter is not rewritten with bare `\n`; `M-/` folds case when it searches and restores the case that was typed.
- **The manual checklists gain an automated half.** `EDITOR_OPEN_FOLDER`, `EDITOR_KEY_LOG` and `EDITOR_PRESENT_LOG`, all unset on an ordinary launch, with every log path resolved in the shell from the launching environment and confined to the cache or temporary directory, a symlink refused by name and again by open handle, because the web view is a trust boundary and the page must not name the file it writes to.

## 0.1.0 — 2026-09-05

The first release cut. It ships phase one, *the deck*: an author opens a folder of Markdown chapters, edits with Emacs bindings, drops images in, presents a chapter as a deck, shapes that deck in the same text, and publishes it to a stable link with a record of every version. Each line below cites the record it reports; the eight intents name their closed specs.

### Added

- **Open a folder and see the book.** Editor opens a folder as a book: each Part is a folder, each Chapter a Markdown file, and the sidebar lists the Sections, Sub-sections and Sub-sub-sections drawn from each chapter's own headings, all ordered by numeric prefix. Clicking a node opens the chapter scrolled to that heading. Renaming a file in the Finder reorders the book and the sidebar reloads on its own; a Markdown file dropped on a Part becomes a chapter there with the next prefix. No index file is written, and the sidebar becomes a drawer at iPad and iPhone widths. (itd-2609051335399446, spc-2609051353137620)
- **Edit with the Emacs bindings I already know.** The editing surface answers the chords in a written binding table, and no chord outside it acts. `C-h b` opens the keys panel listing every action with its live chords; `C-g` or Escape cancels a search, a panel, an overlay or a half-typed prefix; `C-x C-s` saves explicitly, the modeline marks an unsaved buffer, and closing or switching chapter with unsaved changes asks. A chapter opened and saved without typing is byte for byte unchanged. (itd-2609051335406422, spc-2609051353381023)
- **Insert a construct I cannot remember.** `C-c i` opens a filterable palette; typing a few letters and Return writes the construct's canonical form at the cursor, with the cursor where the content goes. This phase offers the rule split, the divider heading, columns, speaker notes, the credit line and the page-break comment; every form is Pandoc-compatible Markdown a plain tool reads past. (itd-2609051335415528, spc-2609051353398011)
- **Drop an image and have it just work.** A file dragged onto a chapter's text is copied into that Part's `assets/` folder and a Markdown reference appears at the drop point with the cursor in the alt text, ready for the caption. Identical bytes dropped again into the same Part reuse the one copy; a phone-native photograph is converted to JPEG on the way in and the original is not kept; EXIF and other metadata are stripped from every copied image; a video file or a pasted video address becomes a `.video` block and any other file becomes a link. Every reference is relative to the chapter and nothing written names the machine. (itd-2609051335420536, spc-2609051353405598)
- **Present a chapter with no slide markup.** `C-c C-p` turns the open chapter into a reveal.js deck in a second window: Sections run left to right, Sub-sections hang beneath them, each one's prose is its speaker notes, Sub-sub-sections fold into their Sub-section's notes, and every image is a full-bleed slide of its own at the place it sits in the text. The deck reflows at phone, tablet and desktop widths, `s` opens the speaker-notes view, and nothing is written into the document folder. (itd-2609051335447894, spc-2609051353412219)
- **Shape the deck in the same text.** A horizontal rule splits a Section into two slides, `{.divider}` on a heading makes a section-break slide, a `.columns` div lays content side by side, a `.notes` div replaces the generated speaker notes, and a `.credit` div puts a source line at the foot of the slide. The article renders the columns in flow, treats the divider as an ordinary heading and omits the notes; the chapter file stays byte for byte what the author typed. (itd-2609051335458626, spc-2609051353425884)
- **Publish and get a link I can open from the lectern.** `C-c C-l` opens the publish panel; one publish renders the deck and the article into a versioned output folder, mints the document's stable id and variant token at first publish, names the version by a hash of its own bytes, commits and pushes into the production repository with the author's own git, and hands back one stable link that always shows the newest version. The presenter shows the same empty shell for no id, a wrong id and an id with nothing beneath it; the panel says every time that an unlisted document is not a private one; gated is selectable and recorded but not enforced in this phase; the app touches the network only during the publish, and only over `https` to a named git remote. (itd-2609051335468596, spc-2609051353438810)
- **Find the version Bob read in March.** Every publish appends an entry to `publish-log.json` in the document folder — timestamp, version hash, variants, the unlisted or gated flag, and links — and the publish panel lists them newest first with open and copy for each. A version folder once written is never written into again; only `latest.json` moves, so an old version link keeps showing what it showed. Republishing unchanged content lands on the hash already on the site and adds a log entry but no second version path. (itd-2609051335479329, spc-2609051353457083)

### Disciplines in force

Ten rules that every intent inherits rather than owns. Six bind from this release; the other four are recorded now and bind from the phase named.

- **Round-trip byte-fidelity.** Any path that reads a chapter and writes it back returns it byte for byte except at the spans the author edited: no reflowed lines, no invented escapes, no realigned tables, no dropped HTML comments, and no renderer ever writes to a chapter file. In force from this release. (itd-2609051336074533)
- **No machine in the document.** Nothing inside a document folder names the author's machine: no absolute path, hostname, username or home directory in any chapter, `document.yaml`, `assets.json` or `publish-log.json`. Public web addresses are references, not machines, and are allowed. In force from this release. (itd-2609051336080960)
- **One source, always.** The text exists once; every rendering is a function of the one parse tree produced by the one core from the chapter files, and no rendering is ever an input. In force from this release. (itd-2609051336090390)
- **Degrade gracefully in a plain tool.** Every extension is one of five forms — a fenced div with attributes, a heading attribute, an image attribute, a bracketed span attribute, or an HTML comment — so a plain Markdown reader reads past every construct and loses no prose. In force from this release, with the first palette entries. (itd-2609051336110536)
- **Legible on three device classes.** Every screen rendering is complete and readable at 390, 820 and 1280 CSS pixels in the current Safari and Chromium engines, with vertical scrolling only and no pinch to read. In force from this release, with the deck. (itd-2609051336128348)
- **Network only on publish.** The app touches the network only during a publish the author started — the push, any upload, applying access and following that publish's pipeline until it reports done or failed — and at no other time; opening, editing, dropping assets and presenting all work offline. In force from this release, with the first publish. (itd-2609051336158553)
- **The renderings agree.** For one source and one variant, the article, the deck and the PDF give the same answer about every citation, footnote, reference list and variant filter, differing only in the presentation the canon's mapping table assigns. Binds from phase 2, when citations arrive with the article. (itd-2609051336130664)
- **Nothing is stored about a reader.** Editor and the pages it publishes keep no reader's marks, notes, preferences or identity, and no published page writes anything back; the one carve-out is the access provider of a gated document. Binds from phase 2, when the article's reader controls arrive. (itd-2609051336145770)
- **Variant fidelity.** A block or span marked for a variant appears only in that variant's renderings and takes its footnotes and citations with it, and no page, link or file reveals that another variant exists. Binds from phase 3, when variant marking arrives. (itd-2609051336107315)
- **Orphan, never guess.** An annotation resolves to the words it was made against or to nothing: when its anchor no longer resolves it is reported as orphaned with its quote and heading path, never re-attached to different words and never silently discarded. Binds from phase 7, with sidecar annotations. (itd-2609051402235443)

### Decisions taken

Five architecture decision records, all accepted on 2026-09-05, and the dated log behind them.

- **The desktop shell is Tauri 2 around a web editing surface.** The system web view renders the editor; Rust owns the file system, hashing, git, the export build and the publish action; one TypeScript rendering core is shared by the app, the single HTML file, the presenter site and the pipeline. Electron stays the named fallback if key interception in the system web view fails. (adr-2609051324137479)
- **A document is a folder of chapters in Pandoc-compatible Markdown with variants.** Part = folder, Chapter = file, Section = H2, Sub-section = H3, Sub-sub-section = H4, ordered by numeric prefix; every extension is one of five plain forms; citations and footnotes are Pandoc's own; variants are a document-model feature declared in `document.yaml`. A private dialect is rejected in favour of the insert palette. (adr-2609051324147479)
- **Publishing pushes to a private GitHub repository deployed by Cloudflare Pages, with stable ids and versioned hashes.** Each document has one unguessable stable id, each variant an unguessable path token, each publish a content hash beneath them with a latest pointer; the author chooses unlisted or gated at publish time; assets above the host's per-file ceiling go to object storage rather than through git; the pipeline renders the PDF. (adr-2609051324157479)
- **The PDF is rendered by Typst in the publish pipeline in a journal layout.** The core emits Typst source with every citation already resolved against the same BibTeX file the article and the deck read, so there is one citation resolver; Pandoc and LaTeX leave the pipeline. Not in this phase's output; recorded here because it fixes the shape of the core. (adr-2609051324167479)
- **Reader annotations live in sidecar files beside chapters, private by default, publishable as layers.** One plain JSON sidecar per chapter, anchored by excerpt and position and re-resolved on load; an anchor that no longer resolves is reported as orphaned; the Markdown never carries annotations and a reader's marks are never sent to the author. Not in this phase's output; it binds the annotation work of phase 7. (adr-2609051324177479)
- **The decision log.** `.abcd/work/DECISIONS.md` carries 104 dated, append-only, one-line decisions taken while this release was built — from the three-tier `.abcd/` layout and the product story through the base32 grammar of every published path segment, the dropped-file nonce, the EXIF strip, the `https`-only site address, the named-remote rule, and the hand-written fenced-div block rule — each of which either graduated to one of the records above or stands as file-scoped rationale.
